Product Requirement Document (PRD) – Tap4Smash (Advanced MVC Monolith)1. Ringkasan Produk (Product Overview)Nama Aplikasi: Tap4SmashArsitektur Teknis: Monolitik Tradisional MVC (CodeIgniter 4, Tailwind CSS, MySQL) – Server-Side Rendered HTML.Integrasi Pihak Ketiga: * Payment Gateway: PaymentKu (Verifikasi otomatis via Webhook/Callback).WhatsApp Gateway: Layanan API Lokal (Fonnte / Wablas / sejenisnya).Tujuan: Menyediakan platform pemesanan lapangan badminton yang cepat, praktis, dan andal bagi pelanggan dengan fleksibilitas pembayaran (DP/Lunas), serta menyediakan dasbor kontrol bagi pengelola GOR untuk mengelola pelunasan di tempat.2. Aturan Bisnis & Arsitektur Status (Business Rules)A. Aturan Transaksi Tap4SmashSewa per Jam: Durasi sewa dihitung per jam penuh (kelipatan 60 menit).Batas Waktu Transaksi: Pengguna wajib menyelesaikan pembayaran di gerbang PaymentKu maksimal 15 menit sejak tombol pesan diklik.Kebijakan Pelunasan: Pengguna yang memilih opsi DP wajib melunasi sisa tagihan di meja kasir GOR sebelum masuk ke area lapangan untuk bertanding.B. Arsitektur Status di Tingkat Database (Tabel bookings)Transisi data dikontrol sepenuhnya oleh logika Controller backend dan disimpan ke dalam dua kolom status terpisah di MySQL:status (Status Jadwal Lapangan):pending: Slot sedang dikunci di halaman checkout atau menunggu pembayaran dari PaymentKu (Warna Kuning).success: Pembayaran awal sukses diverifikasi PaymentKu, lapangan resmi terjadwal milik user (Warna Merah).expired / failed: Gagal menyelesaikan pembayaran dalam 15 menit (Slot otomatis kembali Hijau).status_pelunasan (Status Keuangan):lunas: User memilih opsi Full 100% di awal, atau user opsi DP yang sudah membayar sisa tagihannya secara tunai di kasir GOR.belum_lunas: User memilih opsi DP 50% dan masih memiliki sisa tagihan yang harus dibayar di tempat.4. Kebutuhan Non-Fungsional (Non-Functional Requirements)Keamanan Webhook PaymentKu: Controller yang menangani callback dari PaymentKu wajib memvalidasi Signature Key resmi untuk mencegah manipulasi status transaksi dari pihak luar.Keamanan Form (CSRF Protection): Karena seluruh interaksi menggunakan form POST tradisional, token keamanan wajib diaktifkan via Config\Filters.php dan dipasang di setiap form menggunakan helper <?= csrf_field() ?>.Normalisasi Input WhatsApp: Backend wajib melakukan pembersihan dan normalisasi string nomor telepon yang diinput user menjadi format standar internasional (628xxxxxxxxxx) sebelum dikirimkan ke API WhatsApp Gateway.Optimasi Aset Tailwind: Proses kompilasi akhir CSS wajib menggunakan flag --minify (npx tailwindcss --minify) untuk memastikan file CSS statis di folder public/css/style.css berukuran sangat kecil (di bawah 20KB) sehingga halaman Tap4Smash dapat dimuat dengan sangat cepat di perangkat mobile pengguna.
